MAKE THE CONTEXT YOUR OWN

Detection thresholds

These are educational defaults, not universal security thresholds. A busy server may legitimately generate thousands of packets, while the same activity from another endpoint might deserve investigation.

A rule triggers only when the observed count is greater than its threshold. Counts cover the entire capture, not a fixed time window.

THE ANALYST MINDSET

How to Think Like an Analyst

  1. Observe unusual behaviour.
  2. Identify the source and destination.
  3. Determine which protocol is involved.
  4. Establish whether the activity is expected.
  5. Look for supporting indicators.
  6. Correlate with endpoint, firewall and other security telemetry.
  7. Decide whether further investigation is required.
An anomaly is a starting point for investigation, not proof of compromise.

FROM WIRESHARK TO THIS WORKSPACE

Bring your own capture

  1. Open Wireshark.
  2. Capture traffic in an authorised environment.
  3. Stop the capture.
  4. Use File → Export Packet Dissections → As CSV. Include the packet-list headings.
  5. Choose your CSV in this tool.

Only analyse traffic from systems and networks you own or are authorised to monitor.

What this tool cannot tell you

CSV omits much of a PCAP’s detail. Encryption limits visibility; NAT and resolved hostnames affect attribution. Protocol labels depend on Wireshark. Volume alone does not establish intent. This tool does not analyse malware or replace Wireshark, an IDS, a SIEM or professional monitoring.

Version 1 does not analyse TCP flags, time windows, DNS domains, PCAP or PCAPNG files.

Detection tells an analyst where to look. Investigation determines what actually happened.
